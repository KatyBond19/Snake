Архитектура проекта «Multiplayer Snake»

## 1. Структура проекта

Проект — монорепозиторий с приложениями клиента и сервера, а также общими пакетами:

### apps/client — основное приложение (React + TypeScript + Vite)

Назначение: браузерный клиент мультиплеерной «Змейки».


apps/client/
├── index.html
├── package.json
├── tsconfig.json
├── vite.config.ts
└── src/
├── main.tsx — точка входа
├── App.tsx — корневой компонент, провайдер роутера
├── router.tsx — конфигурация маршрутов
├── pages/ — страницы приложения
│ ├── HomePage.tsx
│ ├── LobbyPage.tsx
│ ├── GamePage.tsx
│ └── NotFoundPage.tsx
└── components/ — компоненты приложения


### apps/server — авторитетный игровой сервер (Node.js + TypeScript + ws)

Назначение: WebSocket-сервер, который создаёт комнаты, проверяет действия игроков и
рассылает актуальное состояние матча. Состояние хранится в памяти процесса; после
перезапуска сервера матчи не восстанавливаются.

apps/server/
├── package.json
└── src/
   ├── index.ts — запуск HTTP-сервера и WebSocket-сервера
   ├── rooms.ts — создание комнат, вход и выход игроков
   └── game.ts — игровой цикл, проверка ходов и столкновений

Сервер принимает направления движения и команды лобби от клиента, но не принимает
от клиента координаты или счёт как источник истины. На каждом игровом тике сервер
обновляет состояние и отправляет снимок комнаты всем её подключённым игрокам.


### packages/shared-types — общие типы протокола и состояния

Назначение: единая типизация WebSocket-сообщений и игровых сущностей для клиента и
сервера; пакет не содержит сетевой или игровой логики.

packages/shared-types/
├── package.json
└── src/
   └── index.ts — типы `ClientMessage`, `ServerMessage`, `RoomState`,
       `PlayerState` и `GameState`


### packages/shared-ui — библиотека общих компонентов

Назначение: переиспользуемые UI-компоненты, не зависящие от бизнес-логики.
packages/shared-ui/
├── package.json
├── tsconfig.json
├── vite.config.ts
└── src/
├── index.ts — публичный API библиотеки
├── Button.tsx — кнопка с вариантами primary/secondary
├── ScoreBoard.tsx — таблица лидеров
├── Button.test.tsx
└── ScoreBoard.test.tsx

## 4. Структура роутинга

| Маршрут            | Страница       | Параметры | Защита |
|--------------------|----------------|-----------|--------|
| `/`                | HomePage       | —         | нет    |
| `/lobby`           | LobbyPage      | —         | нет    |
| `/game/:roomId`    | GamePage       | `roomId`  | нет (в MVP) |
| `*`                | NotFoundPage   | —         | —      |

Вложенности нет: все маршруты плоские. Страница `/game/:roomId` использует параметр `roomId` для идентификации комнаты. Защищённые маршруты в MVP не предусмотрены (нет аутентификации).


## 5. Игровое состояние и WebSocket-протокол

Сервер хранит `Room` с идентификатором, статусом (`waiting`, `playing` или
`finished`), настройками поля, набором игроков и текущим снимком матча. Игрок
содержит идентификатор соединения, имя, очки и состояние змейки (упорядоченные
координаты сегментов, направление и признак жизни). Матч хранит номер тика,
состояние еды и змей; сервер в памяти поддерживает комнаты в `Map<roomId, Room>`.
Размер комнаты ограничен 2–8 игроками.

Все сообщения — JSON-объекты с полем `type`; конкретные поля и варианты `type`
объявлены в `packages/shared-types` и используются обеими сторонами.

| Направление | Тип сообщения | Назначение |
|-------------|---------------|------------|
| Клиент → сервер | `room:create` | Создать комнату и войти в неё |
| Клиент → сервер | `room:join` | Войти в комнату по её идентификатору |
| Клиент → сервер | `game:start` | Запустить матч из лобби |
| Клиент → сервер | `game:input` | Передать новое направление своей змейки |
| Клиент → сервер | `room:leave` | Выйти из комнаты |
| Сервер → клиент | `room:joined` | Подтвердить вход и отправить текущее состояние лобби |
| Сервер → клиент | `room:updated` | Уведомить о составе комнаты и её статусе |
| Сервер → клиент | `game:state` | Передать авторитетный снимок игрового состояния |
| Сервер → клиент | `server:error` | Сообщить об отклонённой команде или ошибке |

Сообщение `game:input` содержит только направление; сервер проверяет допустимость
поворота, обновляет змейку на очередном тике и сам рассчитывает столкновения,
гибель и очки. `game:state` содержит номер тика, поле, еду и публичные данные
игроков. Доступ к комнатам и состоянию матча предоставляется только через
WebSocket-обработчики сервера.


## 6. Использование библиотеки shared-ui основным приложением

Основное приложение импортирует компоненты из `@snake/shared-ui`:

```tsx
import { Button, ScoreBoard } from '@snake/shared-ui'
Button используется на HomePage, LobbyPage, NotFoundPage.

ScoreBoard используется на GamePage.
Связь пакетов обеспечена через npm workspaces (поле workspaces в корневом package.json).
