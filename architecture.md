Архитектура проекта «Multiplayer Snake»

## 1. Структура проекта

Монорепозиторий содержит клиент, сервер, общую UI-библиотеку и пакет типов протокола:

### apps/client — основное приложение (React + TypeScript + Vite)

Назначение: браузерный клиент мультиплеерной «Змейки».


apps/client/
├── index.html
├── package.json
├── tsconfig.json
├── vite.config.ts
└── src/
├── main.tsx — точка входа
├── App.tsx — корневой компонент, провайдер роутера
├── router.tsx — конфигурация маршрутов
├── network/
│   └── gameSocket.ts — WebSocket-клиент и общий протокол сообщений
├── pages/ — страницы приложения
│ ├── HomePage.tsx
│ ├── LobbyPage.tsx
│ ├── GamePage.tsx
│ └── NotFoundPage.tsx
└── components/ — компоненты приложения


### packages/shared-ui — библиотека общих компонентов

Назначение: переиспользуемые UI-компоненты, не зависящие от бизнес-логики.
packages/shared-ui/
├── package.json
├── tsconfig.json
├── vite.config.ts
└── src/
├── index.ts — публичный API библиотеки
├── Button.tsx — кнопка с вариантами primary/secondary
├── ScoreBoard.tsx — таблица лидеров
├── Button.test.tsx
└── ScoreBoard.test.tsx

### packages/shared-types — общий контракт клиента и сервера (TypeScript)

Пакет `@snake/shared-types` содержит типы состояния матча и комнат, discriminated
union типов сообщений WebSocket, а также проверку входящих JSON-сообщений.

```text
packages/shared-types/
├── package.json
├── tsconfig.json
├── src/
│   └── index.ts — модели состояния и протокол сообщений
└── tests/
    └── protocol.test.ts — проверка корректных и некорректных сообщений
```

Клиент и сервер импортируют этот пакет по имени. Сообщения клиента:
`room:join`, `room:leave`, `game:start`, `game:turn`. Сообщения сервера:
`room:joined`, `room:state`, `game:state`, `error`.

### apps/server — авторитетный сервер (Node.js + TypeScript + ws)

Сервер принимает WebSocket-соединения по `/ws` и предоставляет HTTP
health-check по `/health`. Комнаты, подключения игроков и состояние игры
хранятся в памяти процесса. В комнате допускается от 2 до 8 игроков.

Сервер задаёт сетку 20×20, направление и сегменты каждой змейки, пищу,
счёт и номер тика. Он проверяет допустимость ходов, рассчитывает столкновения,
обновляет состояние по таймеру и рассылает его игрокам. При отключении игрока
его змейка удаляется; состояние комнаты обновляется для оставшихся игроков.

```text
apps/server/
├── package.json
├── tsconfig.json
└── src/
    ├── index.ts — запуск HTTP/WebSocket-сервера
    ├── server.ts — health-check, транспорт и диспетчеризация сообщений
    ├── RoomManager.ts — создание комнат, подключения и рассылка состояния
    ├── GameRoom.ts — модель комнаты, змейки, ходы и столкновения
    ├── GameRoom.test.ts — тесты правил комнаты и симуляции
    └── server.test.ts — интеграционные HTTP/WebSocket-тесты
```

Проект входит в npm workspace `apps/*`; общие типы — в `packages/*`.

## 3. Компоненты

### packages/shared-ui
| Компонент     | Назначение                                      |
|---------------|-------------------------------------------------|
| `Button`      | Кнопка с вариантами `primary` / `secondary`     |
| `ScoreBoard`  | Таблица лидеров (сортировка по очкам)           |

### apps/client
| Компонент       | Назначение                                   |
|-----------------|----------------------------------------------|
| `GameCanvas`    | Игровое поле (canvas)                        |
| `HomePage`      | Главная страница                             |
| `LobbyPage`     | Лобби ожидания игроков                       |
| `GamePage`      | Страница игры                                |
| `NotFoundPage`  | Страница 404                                 |

### apps/server
| Компонент     | Назначение                                                        |
|---------------|-------------------------------------------------------------------|
| `server`      | HTTP health-check, WebSocket-транспорт и обработка команд         |
| `RoomManager` | Создание комнат, подключение игроков и рассылка состояний         |
| `GameRoom`    | Состояние матча, симуляция сетки, обработка ходов и столкновений  |

### packages/shared-types
| Компонент           | Назначение                                                     |
|---------------------|----------------------------------------------------------------|
| `ClientMessage`     | Типы команд присоединения, выхода, старта матча и смены хода   |
| `ServerMessage`     | Типы уведомлений о комнате, состоянии игры и ошибках           |
| `parseClientMessage`| Проверка входящих JSON-команд перед обработкой сервером        |
| `parseServerMessage`| Проверка серверных сообщений клиентом                          |


## 4. Структура роутинга

| Маршрут            | Страница       | Параметры | Защита |
|--------------------|----------------|-----------|--------|
| `/`                | HomePage       | —         | нет    |
| `/lobby`           | LobbyPage      | —         | нет    |
| `/game/:roomId`    | GamePage       | `roomId`  | нет (в MVP) |
| `*`                | NotFoundPage   | —         | —      |

Вложенности нет: все маршруты плоские. Страница `/game/:roomId` использует параметр `roomId` для идентификации комнаты. Защищённые маршруты в MVP не предусмотрены (нет аутентификации).


## 5. Использование библиотеки shared-ui основным приложением

Основное приложение импортирует компоненты из `@snake/shared-ui`:

```tsx
import { Button, ScoreBoard } from '@snake/shared-ui'
Button используется на HomePage, LobbyPage, NotFoundPage.

ScoreBoard используется на GamePage.
Связь пакетов обеспечена через npm workspaces (поле workspaces в корневом package.json).
