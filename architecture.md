Архитектура проекта «Multiplayer Snake»

## 1. Структура проекта

Целевая структура — монорепозиторий с двумя приложениями и библиотекой общих компонентов:

### apps/client — основное приложение (React + TypeScript + Vite)

Назначение: браузерный клиент мультиплеерной «Змейки».


apps/client/
├── index.html
├── package.json
├── tsconfig.json
├── vite.config.ts
└── src/
├── main.tsx — точка входа
├── App.tsx — корневой компонент, провайдер роутера
├── router.tsx — конфигурация маршрутов
├── pages/ — страницы приложения
│ ├── HomePage.tsx
│ ├── LobbyPage.tsx
│ ├── GamePage.tsx
│ └── NotFoundPage.tsx
└── components/ — компоненты приложения


### packages/shared-ui — библиотека общих компонентов

Назначение: переиспользуемые UI-компоненты, не зависящие от бизнес-логики.
packages/shared-ui/
├── package.json
├── tsconfig.json
├── vite.config.ts
└── src/
├── index.ts — публичный API библиотеки
├── Button.tsx — кнопка с вариантами primary/secondary
├── ScoreBoard.tsx — таблица лидеров
├── Button.test.tsx
└── ScoreBoard.test.tsx

### apps/server — авторитетный игровой сервер (Node.js + TypeScript)

Назначение: сетевые комнаты и единое серверное состояние матча. Сервер проверяет
ввод игроков, выполняет игровую симуляцию и рассылает обновления подключённым
клиентам; клиенты не определяют исход столкновений или счёт.

Для обмена состоянием используется WebSocket-соединение. Сервер управляет
лобби, подключениями и жизненным циклом комнат; после отключения игрока его
змейка удаляется из текущего матча.

Предлагаемая структура серверного проекта:

```text
apps/server/
├── package.json
├── tsconfig.json
└── src/
    ├── index.ts — запуск сервера и подключение транспорта
    ├── rooms/
    │   └── RoomManager.ts — создание лобби и управление комнатами
    ├── game/
    │   ├── GameRoom.ts — жизненный цикл матча и игроки
    │   └── engine.ts — авторитетная игровая симуляция и столкновения
    └── network/
        └── protocol.ts — типы сообщений между клиентом и сервером
```

Проект входит в MVP; корневой npm workspace `apps/*` уже охватывает этот путь.

## 4. Структура роутинга

| Маршрут            | Страница       | Параметры | Защита |
|--------------------|----------------|-----------|--------|
| `/`                | HomePage       | —         | нет    |
| `/lobby`           | LobbyPage      | —         | нет    |
| `/game/:roomId`    | GamePage       | `roomId`  | нет (в MVP) |
| `*`                | NotFoundPage   | —         | —      |

Вложенности нет: все маршруты плоские. Страница `/game/:roomId` использует параметр `roomId` для идентификации комнаты. Защищённые маршруты в MVP не предусмотрены (нет аутентификации).


## 5. Использование библиотеки shared-ui основным приложением

Основное приложение импортирует компоненты из `@snake/shared-ui`:

```tsx
import { Button, ScoreBoard } from '@snake/shared-ui'
Button используется на HomePage, LobbyPage, NotFoundPage.

ScoreBoard используется на GamePage.
Связь пакетов обеспечена через npm workspaces (поле workspaces в корневом package.json).
